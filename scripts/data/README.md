# `scripts/data/`

Static reference data checked into the repo so fixes are reproducible without
re-downloading multi-hundred-megabyte sources.

## `city-county-map.json`

Maps `"<normalised city>|<STATE>"` → real county name, e.g. `"cary|NC"` → `"Wake"`.

**Built 2026-08-09** to fix MASTER-PLAN **Defect B** — the scraper seed data was
generated by appending `" County"` to the city name, producing ~2,000 values like
`"Bainbridge County"` that are not real counties. `getCountyCentroid()` returned
`null` for all of them, so the county tier of the geocoding chain was dead and
those events fell through to the **state** centroid.

### Sources — both free, authoritative, redistributable

| Source | Used for | Licence |
|---|---|---|
| [US Census Bureau 2023 National Counties Gazetteer](https://www2.census.gov/geo/docs/maps-data/data/gazetteer/2023_Gazetteer/2023_Gaz_counties_national.zip) | county FIPS → county name + centroid (`INTPTLAT`/`INTPTLONG`) for all 3,222 US counties | US Government work, public domain |
| [GeoNames US dump](https://download.geonames.org/export/dump/US.zip) (`US.txt`) | populated place → county FIPS (`admin2`) | CC BY 4.0 |

The two are joined on `state + county FIPS`. Only GeoNames feature class `P`
(populated places) is used, and only each place's **official** and **ascii**
names — `alternatenames` was tried and rejected because it carries historical and
neighbouring-place names that produced flatly wrong joins (`Great Neck, NY`
resolved to Suffolk County when it is in Nassau). Where a city name repeats
within a state, the highest-population place wins.

### Normalisation

Keys are lowercased, punctuation-stripped, and abbreviation-expanded so both
sides of the join agree: `st`→`saint`, `ste`→`sainte`, `mt`→`mount`, `ft`→`fort`.
Configs write `St. Augustine` where GeoNames writes `Saint Augustine`; without the
expansion that cost 40+ real matches.

### Verification done before it was applied

- **31/31** independently-known city→county pairs correct (Boston→Suffolk,
  Pittsburgh→Allegheny, Buffalo→Erie, Miami→Miami-Dade, …).
- Census centroids compared against the 405 pre-existing hand-entered values:
  only **2** disagreed by >40km, both because a Census *internal point* can sit
  offshore (San Francisco's is ~54km out near the Farallon Islands). Existing
  values were therefore **kept**, never overwritten.
- Result: unresolved county entries fell **2,948 → 57**.

### Known limits — stated, not hidden

- **Connecticut is mid-transition.** Census 2023 replaced CT's eight traditional
  counties with nine Planning Regions as county equivalents, so this dataset
  returns e.g. `Capitol Planning Region` for Hartford. `county-centroids.js`
  carries **both** forms. Entries whose county already resolved were deliberately
  left alone, which is why ~292 "disagreements" (nearly all CT) were not rewritten
  — they are a vintage difference, not an error.
- **Virginia independent cities** are county equivalents, so Norfolk resolves to
  `Norfolk city`, not a surrounding county. That is correct per Census.
- ~26 small places are absent from GeoNames and ~24 config entries have no `city`
  field to look up; those keep their original value and are reported by the script.

## Regenerating

The build script lives in the session scratchpad rather than the repo because it
needs the 71MB GeoNames download. To rebuild: download both sources above, join on
`state + county FIPS`, filter to feature class `P`, and apply the normalisation
described here. Consumer: `scripts/fix-fabricated-counties.js`.
